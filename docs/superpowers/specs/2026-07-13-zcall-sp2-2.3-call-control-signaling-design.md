# SP2 step 2.3 — Call-control signaling: ring + receive (design)

**Date:** 2026-07-13
**Parent decisions:**
- [GO verdict — key = sessId[0:30]](../decisions/2026-07-13-zcall-keying-GO-verdict.md)
- Prev: [InitZRTP handshake (2.1)](2026-07-13-zcall-sp2-initzrtp-handshake-design.md), [SRTP media (2.2)](2026-07-13-zcall-sp2-2.2-srtp-media-design.md)

**Status:** approved (brainstorming) → ready for writing-plans.

## Goal

Make the callee's phone ring from Linux by invoking the app's own `sendRequestCall`
(`voicecall/request`) via CDP — the missing piece that `requestcall` alone does not do. When the
operator answers, the peer streams media through the relay and the `MediaSession` (2.2) decrypts
the real inbound media, proving a connected call and completing the 2.2 live validation. `endCall`
on exit so no dangling call is left server-side.

**Why this step exists:** live-media (2.2) showed `inboundAuthOk 0` with the phone NOT ringing.
`requestcall` only allocates the call server-side; the callee is notified by a separate
`voicecall/request` signal. All the call-control endpoints live in the same webpack bundle we
already invoke, so they are reachable by CDP exactly like `requestCall`.

## Global Constraints

- **Boundary (binding):** operator's own account / machine / **own phone** only. This step
  actually RINGS a phone — only ever the operator's own. `sessId`/relay-addresses not committed;
  live output redacted; `endCall` always runs on exit.
- **No `Co-Authored-By` / AI-attribution** anywhere. Commit only when asked.
- **Runtime:** Node.js + CDP (reuse `tools/zcall-signaling`), plus the 2.1/2.2 tools. No new native.

## Reverse-engineered signaling signatures (from the running bundle)

The VoiceCall API builder module (`r.default`; facade wraps each) — endpoint IDs 11300–11306:
```
requestCall(calleeId, callId, codec, typeRequest)                 -> voicecall/requestcall (11300)
   params: { calleeId, callId, codec:"[]", typeRequest, imei }

sendRequestCall(calleeId, rtcpAddress, rtpAddress, codec,
                extendData, session, callId)                       -> voicecall/request     (11301)  ← RINGS
   params: { calleeId, rtcpAddress, rtpAddress, codec, session, callId, imei
             (+ extendData, subCommand:3 when extendData set) }

sendRingRingCall(callerId, callId)                                 -> voicecall/ringring    (11302)
   params: { callerId, callId, status:0, imei }

sendAnswerCall(callerId, callId, status, codec, extendData,
               rtcpAddress, rtpAddress, session_id)                -> voicecall/answer      (11303)
sendAnswerACKCall(calleeId, callId)                                -> voicecall/answerack   (11304)
sendCancelCall(callerId, callId, callType)                         -> voicecall/cancel      (11305)
sendEndCall(uidTo, callId)                                         -> voicecall/endcall     (11306)
   params: { uidTo, callId, status:3, imei }
```
All params are zpw-`encodeAES`'d into `&params=`; every call is a `_get`. Facade arg order for
`sendRequestCall` = `(calleeId, rtcpAddress, rtpAddress, codec, extendData, session, callId)`.

## Architecture

### 1. `tools/zcall-signaling/cdp-invoke.js` — generalize
- Add `buildVoiceCallExpr({ method, args })` — a pure builder (like the existing
  `buildInvokeExpr`) that webpack-grabs the require cache, finds the module/object exposing
  `ex[method]` (or `ex.default[method]`) as a function, calls `api[method](...args)`, and returns
  `JSON.stringify(result ?? { ok: true })`. `args` are JSON-embedded literals.
- Add `invokeVoiceCall({ method, args, port = 9222 })` — attaches CDP to the index.html page and
  evaluates `buildVoiceCallExpr`, returning the parsed result.
- Refactor `invokeRequestCall` to delegate: `invokeVoiceCall({ method: 'requestCall',
  args: [String(calleeId), callId, '[]', Number(type)] })`. Existing behavior/tests preserved.

### 2. `tools/zcall-signaling/call-control.js` — pure helpers + invokers
- `buildRingArgs({ config, callId, relayAddr, addrSource = 'config' }) → Array` — positional args
  for `sendRequestCall`:
  `[ String(config.toId), rtcp, rtp, '[]', '', config.sessId, callId ]`, where `(rtp, rtcp)` come
  from `addrSource`: `'config'` → `config.rtpIP`/`config.rtcpIP`; `'server0'` →
  `config.servers[0].rtpaddr`/`.rtcpaddr`; `'relay'` → the InitZRTP `relayAddr` `"ip|port"`.
- `ring({ calleeId, callId, config, relayAddr, addrSource, port }) → Promise` →
  `invokeVoiceCall({ method: 'sendRequestCall', args: buildRingArgs(...) })`.
- `endCall({ uidTo, callId, port }) → Promise` →
  `invokeVoiceCall({ method: 'sendEndCall', args: [String(uidTo), callId] })`.

### 3. `tools/zcall-media/live-call.js` — operator CLI (own call)
Flow: `invokeRequestCall` → config; `handshake` (2.1) → `relayAddr`; `ring` → callee rings; open
`MediaSession` (2.2) to `relayAddr`; send synthetic payloads + receive/decrypt inbound for ~20 s;
`endCall` in a `finally`. Prints a **redacted** summary: `rang` (ok/err), `inboundAuthOk n`,
`authfail n`, observed inbound `flowToken` (masked), relay (masked). `--addr <config|server0|relay>`
flag selects the `sendRequestCall` address source for quick live iteration.

## Data flow
```
requestCall → config { sessId, toId, servers, rtpIP/rtcpIP }
handshake(2.1) → relayAddr
sendRequestCall(calleeId, rtcp, rtp, "[]", "", sessId, callId)  → CALLEE PHONE RINGS
[operator answers] → peer → relay → MediaSession.unprotect → real inbound media
endCall(toId, callId)  on exit
```

## Testing
- **Offline (suite):**
  - `buildRingArgs` — asserts the positional arg array + values for each `addrSource`, from a
    synthetic config.
  - `buildVoiceCallExpr` — asserts the generated JS embeds the method name + JSON args and calls
    `api[method](...)` (string assertions, mirrors the existing `buildInvokeExpr` test). No network.
- **Live (operator, manual):** `live-call.js` — the phone rings; on answer, `inboundAuthOk ≥ 1`.
  Record the redacted result + which `--addr` source worked in the §B decision doc.

## Open items (resolved live)
- **rtp/rtcpAddress value/format** for `sendRequestCall`: try `--addr config|server0|relay` until
  the phone rings and media returns.
- **Whether media flows without `answerack`:** if inbound arrives after answering, no answerack
  needed; if not, that requires receiving the callee's pushed `answer` signal (full state machine)
  — out of scope for 2.3, tracked for a later step.
- **codec / extendData** exact values (default `"[]"` / `""`).

## Error handling / boundary
- Only ever rings the operator's own phone. `endCall` runs in a `finally` (even on error/timeout)
  to avoid a dangling server-side call. Invoke failures fail loud with the underlying message.
  No `sessId`/relay/addr printed unmasked or committed.

## What this explicitly does NOT cover
- Receiving server-pushed `answer`/`ringring` signals (full caller state machine) — later.
- opus audio (step 3); wiring into `$zcall` / the deb (step 4).

## Success criteria
1. `npm`/suite offline tests for `buildRingArgs` + `buildVoiceCallExpr` pass; existing
   signaling/media tests still green.
2. `live-call.js` against the operator's own number makes the phone ring, and on answer reports
   `inboundAuthOk ≥ 1` (peer's real media decrypted on Linux), then cleanly `endCall`s.
