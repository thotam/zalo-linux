**Date:** 2026-07-13
**Parent decisions:**

## Goal

Duplex SRTP media on Linux: build an RTP packet → `srtp_protect` (libsrtp, master key =
`sessId[0:30]`) → wrap the 5-byte zrtc prefix → send UDP to the relay `:4200`; and reverse it on
inbound (strip 5B → `srtp_unprotect` → RTP). The payload is opaque bytes in this step (real opus is
step 3). Validated live by decrypting the peer's real inbound media + a send smoke test.

Because `ZaloCall.exe` **is** libsrtp with the same policy, using the same libsrtp + policy yields a
byte-identical wire to the real engine — no reimplementation risk.

## Global Constraints

- **Boundary (binding):** operator's own account / own machine / own phone only; own traffic only.
  Per-call `sessId`/keys/relay-addresses and any pcap are ephemeral secrets — never committed;
  live artifacts git-ignored; live output redacted.
- **No `Co-Authored-By` / AI-attribution** in any commit or file. Commit only when asked.
- **Profile:** `SRTP_AES128_CM_HMAC_SHA1_80`, master key = `sessId[0:30]` (16-byte key + 14-byte
  salt), standard RFC 3711 KDF, 10-byte tag, SSRC = fromId (outbound). Same key both directions.
- **Wire (§B):** media packet = `[0]=0x03 (AUDIO_RTP)` + `[1..4]=flowToken` + `<standard SRTP
  packet>` (RTP starts at offset 5). RTP header = base 12 B + `0xBEDE` one-word extension = 20 B.
- **Portability (per native-lib-portability-playbook):** static-pin **libsrtp2 v2.6.0** with its
  internal crypto (no OpenSSL) into the `.node`; `-Wl,--exclude-libs,ALL`; build on the oldest
  supported distro (ubuntu-22.04); **no new deb Depends**.
- **Runtime scope:** step 2.2 builds the addon against **local Node** for `tools/` tests. Building
  against Electron headers + bundling into the shipped app/deb is **step 4** (not here).

## Architecture

### 1. `nativelibs/zsrtp/` — N-API C++ addon (node-addon-api, static libsrtp2)
Mirrors the `nativelibs/mp4thumb` layout: `binding.gyp`, `src/zsrtp.cpp`, `scripts/build-deps.sh`
(fetch+build libsrtp2 static into a content-addressed `.deps-prefix`), `scripts/deps-hash.js`,
`package.json`, `__tests__/`.

Exposed JS API:
```
class ZSrtp {
  constructor({ key: Buffer(30), ssrc: uint32 })   // policy AES_CM_128_HMAC_SHA1_80;
                                                    // outbound stream ssrc; inbound ssrc_any_inbound
  protect(rtp: Buffer): Buffer                      // srtp_protect — RTP in, SRTP out (+10B tag)
  unprotect(srtp: Buffer): Buffer                   // srtp_unprotect — SRTP in, RTP out
}
```
- One `srtp_t` for outbound (ssrc = fromId) and one policy entry `ssrc_any_inbound` for receive, in
  a single session or two sessions. libsrtp manages ROC/replay per SSRC internally.
- C++: `srtp_init()` once (guarded), build `srtp_policy_t` via
  `srtp_crypto_policy_set_aes_cm_128_hmac_sha1_80` for RTP+RTCP, `key` = the 30-byte master key,
  `srtp_create`. `protect`/`unprotect` copy the input Buffer to a working buffer with room for the
  tag, call the libsrtp fn, return a Buffer of the resulting length; throw on any `srtp_err_status`.
- `binding.gyp`: `sources:[src/zsrtp.cpp]`, include the deps-prefix `/include`, `-l:libsrtp2.a`,
  `-Wl,--exclude-libs,ALL`, `-lm -lpthread` (no ssl/crypto — internal crypto). node-addon-api,
  `-std=c++17 -fexceptions`.

### 2. `tools/zcall-media/` JS framing (pure Node)
- `rtp.js` — `buildRtpPacket({ pt=112, seq, timestamp, ssrc, ext=0xBEDE, payload }) → Buffer`
  (v2 header, one-word `0xBEDE` extension, payload appended); `parseRtpPacket(buf)` reuses the
  existing `srtp-decrypt.js parseRtpHeader` for header boundaries.
- `media-frame.js` — `wrapZrtc(type=0x03, flowToken:Buffer(4), srtp:Buffer) → Buffer` and
  `unwrapZrtc(wire) → { type, flowToken:Buffer(4), srtp:Buffer }` (5-byte prefix §B.1).
- `media-session.js` — `MediaSession` over `dgram` to `relayAddr`:
  - `send(payload:Buffer)`: increments seq (+1) and timestamp (+960), `buildRtpPacket` →
    `zsrtp.protect` → `wrapZrtc(0x03, flowToken, …)` → UDP to relay.
  - inbound handler: `unwrapZrtc` → `zsrtp.unprotect` → `parseRtpPacket` → emit
    `{ rtp, payload, flowToken }`. Records the first observed inbound `flowToken`.
  - Config: `{ key, ssrc, relayAddr, flowToken? }`. Fail-loud on key length ≠ 30.

### 3. `tools/zcall-media/live-media.js` — operator CLI (own call)
Runs the 2.1 handshake to get `relayAddr` + config, opens a `MediaSession`, then for ~10 s: sends
K synthetic RTP payloads (e.g. zero/tone bytes — NOT audio) and receives+unprotects the peer's real
inbound media. Prints a **redacted** summary: `inboundAuthOk n/m`, the observed inbound `flowToken`
(masked), bytes sent/received. Never prints key / raw IP.

## Data flow
```
sessId → key = sessId[0:30];  handshake (2.1) → relayAddr
MediaSession(key, ssrc = fromId, relayAddr):
  out: payload → RTP(pt112, ssrc=fromId, 0xBEDE) → srtp_protect → [03|flowToken|srtp] → relay:4200
  in : relay → [03|flowToken|srtp] → srtp_unprotect → RTP → payload
```

## Open items resolved in 2.2
- **Outbound flowToken** (what value the relay expects from us): the 0x02 reply does not echo our
  probe nonce (found in 2.1), so observe the **inbound** flowToken from the peer's live media,
  compare candidates (our probe nonce vs a relay-assigned id), and make `flowToken` a
  `MediaSession` config with a documented default. Resolve during the live test.
- **Inbound SSRC + mid-stream ROC:** use `ssrc_any_inbound`; libsrtp infers ROC from the seq it
  first sees. Note the **re-key boundary** (§B.3 — each sessId keys media only from its own InitZRTP
  onward); a short live test stays within one sessId. If inbound auth fails, it likely crossed a
  re-key — capture the sessId at the segment start.

## Testing
- **Offline (in suite; requires the addon built locally):**
  - `zsrtp` round-trip: `protect` then `unprotect` a synthetic RTP packet with a known 30-byte key
    + ssrc → recovers the payload.
  - **cross-check** native ↔ pure-Node: feed the native `protect` output to the existing
    `tools/zcall-media/srtp-decrypt.js` (keys via `srtp-kdf.js` from the same 30-byte master) →
    `authOk === true`. This proves the native path matches the pure-Node path already validated
    `authOk 10/10` on real wire.
  - framing round-trip: `wrapZrtc`/`unwrapZrtc`, `buildRtpPacket`/`parseRtpPacket`.
- **Offline parity (operator, git-ignored data):** native `unprotect` on a real captured media
  packet → `authOk`, matching `decrypt-capture.js`.
- **Live (operator, manual):** `live-media.js` — `inboundAuthOk ≥ 1` on the peer's real media +
  a send smoke (no crash, relay accepts). Record the redacted result in the §B decision doc.

## What this explicitly does NOT cover
- opus encode/decode + mic/speaker capture → step 3.
- Wiring into `$zcall` / replacing `patch-zcall-linux-stub.js` + building the addon against Electron
  headers and shipping it in the deb → step 4.
- RTCP (SR/RR) unless the relay requires it for media to flow (revisit if the live test shows so).

## Success criteria
1. `nativelibs/zsrtp` builds locally (node-gyp) and its round-trip + cross-check tests pass.
2. The framing + `media-session` unit tests pass in the suite.
3. `live-media.js` against the operator's own call reports `inboundAuthOk ≥ 1` (peer's real media
   decrypted on Linux) and completes the send smoke without error.
